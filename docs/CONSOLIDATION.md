# How this tree was consolidated (2026-09-14)

Three working repositories were merged into this one tree, at the code level, with the newest one (`mopd_domains`)
as the base. The originals were left untouched; this document records every decision so that any file can be traced
back (see also `MAPPING.md`, generated by the build, and `docs/LAYOUT.md` for the tree).

| original repo | what it held | how it survives here |
|---|---|---|
| `mopd` | the paper implementation: OT3 SFT, trl GRPO experts, MOPD (train_mopd), 6-bench eval, graders, data prep | the core package `mopd/` (65 files byte-identical apart from path/import rewrites), `configs/sft/ot3_*`, `configs/legacy_trl/`, `scripts/legacy/` |
| `mopd_domains` | the medical / law / finance / IF extension: pools, big-teacher distillation, domain OPD / MOPD driver, domain eval + graders, NeMo exact-match env, every OPD / MOPD config and launcher | sub-packages `mopd/{data,eval,graders}/domains/`, `mopd/teacher/`, `mopd/distill/train_opd.py`, `mopd/rl/nemo/envs/exactmatch_environment.py`, `configs/{sft,opd,mopd}`, most of `scripts/`, `tools/` |
| `mopd_rl` | NeMo-RL v0.7.0 teacher training: IF / code / math environments, judge validation, ray launcher; plus a copy of `mopd/mopd` | `mopd/rl/nemo/` (envs, judge_eval, prep scripts, unified `run_grpo.py`), `scripts/rl_nemo.sh` + `scripts/nemo/ray.sub`, `configs/rl/`, `env/nemo_extras/` (vendored deps), `mopd/graders/sandbox.py` (its newer variant) |

## 1. Principles

1. **One package.** `mopd` (the paper implementation) is the trunk; everything domain-specific became a sub-package of the
   namespace it extends (`mopd.graders.domains`, `mopd.eval.domains`, `mopd.data.domains`) or a new namespace
   (`mopd.teacher`, `mopd.rl.nemo`). No module is imported through a sibling repo any more; `PYTHONPATH` = the repo root.
2. **One launcher set.** Every duplicated sbatch pair (1-node / 2-node, single-domain / multi-domain, per-domain submit
   scripts) became one script parameterised by `-N` and environment variables. All of them derive the repo path from
   `MOPD_REPO`, else the Slurm submit directory, else their own location (`scripts/_common.sh`), so the tree is relocatable.
3. **One config tree.** `configs/{sft,rl,opd,mopd}` hold the configs of the runs that were actually made, renamed into a
   consistent scheme; every ablation lives in `variants/`; the paper-recipe configs in `legacy_trl/`. SFT / OPD / MOPD
   configs use repo-relative paths; NeMo-RL configs keep absolute paths because ray workers do not share the submit cwd.
4. **Assets stay where they are.** Models, data, outputs and logs are symlink farms into the original repos
   (`setup_cluster.sh`, idempotent); the canonical teacher names `models/teacher-{law,law-rlonly,fin,if,med}` replace the
   run-specific directory names. Big trace teachers and judges live in `$S/past/models`.
5. **Nothing silently changed behaviour.** Logic edits were limited to what the move required (below); everything else is a
   byte-identical copy plus mechanical rewrites of import statements, script names and absolute paths.

## 3. What changed at the code level

Classification of all 171 non-config files against their originals (`third_party/` and `configs/` excluded; the full

| class | files | meaning |
|---|---|---|
| identical | 65 | byte-identical copy of the origin file (the whole paper package `mopd/common, sft, distill, graders, eval, data, rl`, the tests, `env/`, `scripts/nemo/ray.sub`; `graders/sandbox.py` is identical to the newer `mopd_rl` variant) |

### 3.1 The four real edits inside the package

| file | change | why |
|---|---|---|
| `mopd/eval/domains/benches.py` | the two hard-coded defaults `DOMAINS_DATA=.../sean/data/domains` and `DOMAINS_TP=.../mopd_domains/third_party` became `data_root()/domains` and `repo_root()/third_party` (from `mopd.common.io`); the env vars still override | the tree must not point at another repo |
| `mopd/graders/domains/graders.py` | `_TP` = `$DOMAINS_TP` or `../../../third_party` (was `../../third_party`) | the module moved one directory deeper (`mopd/graders/domains/`); caught by the self-check |
| `mopd/graders/sandbox.py` | the `mopd_rl` variant was taken instead of the `mopd` one (+8 lines: an `RLIMIT_AS` memory cap for graded code) | the only file that differed between the two copies of the paper package |
| `tests/test_domain_graders.py` | `import os` + `sys.path` relative to the test file (was `sys.path.insert(0, ".")`) | the original relied on being run from the repo root; caught by the self-check |

`mopd/distill/train_opd.py` (the domain OPD / MOPD driver) changed only in its docstring; its logic is the original
`train_opd_domains.py`. `mopd/rl/nemo/run_grpo.py` is the union of the two former entrypoints (`run_grpo_domains.py`
registered `domain_exactmatch`, `run_grpo_mopdrl.py` registered `mopd_if` / `mopd_code` / `math_with_judge` plus the two
data processors); it now registers all four environments and both processors and puts the repo root on `sys.path`.
`mopd/teacher/merge_teachers.py` generalises the two ad-hoc merge scripts (uniform and 0.4/0.4/0.1/0.1) into one CLI
(`--teachers name=path,... --weights name=w,... --base --out`, writes `merge_info.json`).

## 7. Phase 2 (2026-09-14 evening): the assets moved in, the old repositories retired

The symlink farm was a transition device. Once no job depended on the original paths any more, every asset was moved
INTO the tree (same filesystem, so directory moves are renames; the file-level symlink directories of the teachers and
RL steps were materialised as hard links, no data was copied twice), the three repositories were reduced to their code
shells and archived under `$S/past/misc/old_repos_2026-09-14/`, and `setup_cluster.sh` became unnecessary.

|---|---|
| `models/` | the base models (`$S/models/Qwen3-*`), `Qwen3-1.7B-OT3`, the teachers as real directories, the merges, `rl_steps/` |
